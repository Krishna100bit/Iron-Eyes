# SIH Barbell Tracker — Phase 1

## Hardware

| Component | Details |
|-----------|---------|
| MCU Board | Seeed XIAO nRF52840 Sense |
| IMU | LSM6DS3TR-C (onboard, I2C addr 0x6A) |
| I2C Bus | i2c0 — SDA=P0.07, SCL=P0.27, fast-mode |
| Power | IMU regulator on GPIO P1.08 (auto-enabled at boot) |
| Status LED | Red=P0.26, Green=P0.30, Blue=P0.06 (active-low) |
| Communication | BLE 5.0 (nRF52840 SoftDevice Controller) |
| Attachment | Magnet to barbell |

## Firmware

- **RTOS**: Zephyr 4.4.0 (NCS v3.4.0)
- **Sampling**: 100 Hz application rate (IMU ODR = 104 Hz)
- **IMU Config**: ±4g accel, ±500°/s gyro
- **BLE**: Custom GATT service, 1 Notify characteristic, 20-byte packets
- **Pipeline**: k_timer (10ms) → k_work → I2C burst read → encode → BLE notify

## Build

**Prerequisites**: NCS v3.4.0 installed at `C:\ncs\v3.4.0`.

Open a PowerShell terminal and run:


## Flash

### Method 1: UF2 bootloader (no programmer needed)

1. Connect the XIAO to USB.
2. **Double-tap** the tiny reset button on the board (quickly, within 0.5s).
3. A USB drive named **"XIAO-SENSE"** (or **"Arduino"**) appears.
4. Copy `C:\SIH\build\app\zephyr\zephyr.uf2` to that drive.
5. The board auto-resets and runs the firmware.

### Method 2: west flash (with J-Link or nrfjprog)

```powershell
# With the NCS environment set (same as build):
west flash --build-dir C:\SIH\build
```

The script will:

## BLE Protocol

### UUIDs

| Item | UUID |
|------|------|
| Service | `4fafc201-1fb5-459e-8fcc-c5c9c331914b` |
| IMU Characteristic (Notify) | `beb5483e-36e1-4688-b7f5-ea07361b26a8` |

### 20-Byte Packet Format

| Offset | Size | Type | Field | Scale |
|--------|------|------|-------|-------|
| 0 | 1 | u8 | protocol_version | Always `0x01` |
| 1 | 2 | u16 LE | sequence_number | Wraps at 65535 |
| 3 | 4 | u32 LE | timestamp_ms | `k_uptime_get_32()` |
| 7 | 2 | i16 LE | ax | ÷ 1000 = m/s² |
| 9 | 2 | i16 LE | ay | ÷ 1000 = m/s² |
| 11 | 2 | i16 LE | az | ÷ 1000 = m/s² |
| 13 | 2 | i16 LE | gx | ÷ 100 = °/s |
| 15 | 2 | i16 LE | gy | ÷ 100 = °/s |
| 17 | 2 | i16 LE | gz | ÷ 100 = °/s |
| 19 | 1 | u8 | crc8 | CRC-8/MAXIM over bytes 0–18 |

**Python struct format**: `"<BHIhhhhhhB"` (20 bytes)

**CRC-8/MAXIM**: Poly=0x31, Init=0x00, RefIn=True, RefOut=True, XorOut=0x00

## Troubleshooting

### IMU not detected
- Check serial log for WHO_AM_I result.
- If WHO_AM_I read fails with I2C error: verify the IMU power regulator is enabled (the board DTS sets `regulator-boot-on`, so it should auto-enable).
- The onboard LSM6DS3TR-C uses I2C address `0x6A`. If `imu.h` has a different address, change `IMU_I2C_ADDR`.

### BLE not advertising
- Check serial log for `bt_enable` errors.
- Ensure `CONFIG_BT=y` and `CONFIG_BT_PERIPHERAL=y` in `prj.conf`.
- Try resetting the board.

### Flashing failure
- **UF2 drive doesn't appear**: Double-tap reset faster (within 0.5s). The orange LED should pulse.
- **west flash fails**: Ensure J-Link or nrfjprog is installed and the board is detected.
- **Board not responding after flash**: Hold reset for 5s, then release. If stuck in a crash loop, enter UF2 mode and reflash.

### Python connection failure
- Ensure Bluetooth is enabled on your laptop.
- Verify "IronLoop" appears in a BLE scanner (e.g., nRF Connect mobile app).
- On Windows, try running as Administrator if BLE permissions are restricted.
- Check that `bleak` is installed: `pip install bleak`.

### CRC failure
- If every packet has CRC errors, the Python decoder's struct format may be out of sync with the firmware. Both must use `"<BHIhhhhhhB"`.
- A single CRC error occasionally is normal during initial connection setup.
